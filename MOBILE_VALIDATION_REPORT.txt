Notes on other reported items (all already resolved / out of scope):
  - The chip-based "Product categories" screen in the older screenshot
    predates commit 0db4058 ("Add category and sub-category dropdown
    picker"). The current CategorySubcategoryPicker uses a native
    Picker with a "Select a sub-category" placeholder at index 0, so
    deselecting a chosen sub-category is already supported by scrolling
    the wheel back to the placeholder.
  - The raw wpcomsh-fatal CSS shown on the payout bank account screen
    was fixed in v1.0.174 by the looksLikeServerDump() sanitizer in
    src/api/nest.ts. Verified: the exact CSS payload from the screenshot
    is caught by the regex (`wpcomsh-fatal|wpcomsh-[\w-]+\s*\{` +
    `<\s*style\b`) so ApiError.friendly collapses to the generic
    "The website is having trouble responding" message before any
    screen renders it.

    the Expo Go / dev-client native runtime when the JS bundle can't
    be fetched. This project does not include expo-updates or
    expo-dev-client and does not publish OTA updates, so app code has
    no path to intercept that error — it fires before app JS runs.
    A production standalone build (EAS Build or expo prebuild +
    expo run:android) does not hit this failure mode because the JS
    bundle is embedded, not fetched.

  Earnings & payouts, Seller dashboard, etc.) is now safe — not just the toast

  Please try again."
