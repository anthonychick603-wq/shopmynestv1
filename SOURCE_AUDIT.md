# Source Audit — The Nest Android App 1.0.3

The Android source was compared with the supplied `shopmynest.com` WordPress backup, including MyNest Unified Marketplace, WooCommerce, WooCommerce Stripe Gateway, Stripe Tax for WooCommerce, and the custom mobile bridge.

## Confirmed website APIs

The app uses the existing MyNest namespaces for public products, authentication, users, seller tools, social features, operations, native checkout, shipping labels, and shipping profiles. Bridge 1.1.0 supplies the remaining buyer-order, reporting, application-status, profile-photo, authentication-fallback, and checkout-compatibility behavior.

## Authentication finding

MyNest Unified Marketplace reads bearer tokens from PHP server variables. On a host that does not forward the standard Authorization header, login can succeed while later protected requests fail. The app and bridge now use a second dedicated mobile token header and an early REST authentication filter.

## Checkout finding

The exact message **“Taxes have not been calculated at the moment.”** is generated by Stripe Tax for WooCommerce after a failed Store API tax calculation. The backup shows:

- WooCommerce tax calculation enabled
- Stripe Tax enabled
- Stripe Tax set to Sandbox/Test mode
- No successful cached Stripe Tax calculation records

Bridge 1.1.0 unloads the Stripe Tax handlers only in Sandbox/Test mode, allowing WooCommerce tax-table fallback for test orders. Live mode is never bypassed.

## Android layout finding

The cart action was part of the scroll content and could sit underneath the custom bottom navigation on some device dimensions. It is now a separate footer above navigation.
