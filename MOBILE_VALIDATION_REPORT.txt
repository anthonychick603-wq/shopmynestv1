Included changes for v1.0.174:
- Belt-and-braces server-dump sanitizer moved to the ApiError construction layer,
  so every screen that renders `err.friendly` inline (Payout bank account,
  Earnings & payouts, Seller dashboard, etc.) is now safe — not just the toast
  host.
- Detector expanded to recognize the WordPress.com `.wpcomsh-fatal` CSS ruleset,
  PHP warnings/notices, `Call to undefined`, `-apple-system`/BlinkMacSystemFont/
  text-wrap-style style fingerprints, and any error string longer than 600
  characters (no legit REST error message reaches that length).
- `request()` also scrubs `data.message` on non-2xx responses before it ever
  reaches an ApiError, in case the WordPress.com atomic layer wraps a fatal
  HTML/CSS blob inside a JSON envelope.
- User-facing server dump fallback: "The website is having trouble responding.
  Please try again."
